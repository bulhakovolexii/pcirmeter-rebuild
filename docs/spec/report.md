# PDF-звіт

Оригінал: `LibControls.UserReportPage` (iTextSharp, сторінка Reports; функції — `features.md` §2.7).
Реалізація: `src/report/report.ts` (`buildReport`, без DOM), UI — `src/ui/ReportDialog.svelte`, `src/ui/report.ts`.

## Що робить оригінал [п — за декомпільованим кодом]

- Один документ на кілька файлів (Shift+клік по вкладках). На файл: таблиця «ІЧ-зображення | Видиме фото»
  (рендери PNG), опційно накладення ІЧ на фото; «General information» — таблиця 4 колонки:
  ім'я файлу, дата, час, ε, T_пов (env), T_відб, вологість, відстань, Max/Min/Avg кадру; опис вимірювання;
  «Additional analysis» — таблиці точок (№, T, ε, T_відб, T_пов, RH, d), ліній і прямокутників (сер./max/min +
  ті самі параметри) і зображення профілю для кожної лінії.
- Поля клієнта/компанії, логотип, RTF — у нас не потрібні (рішення I-07).

## Наш звіт

A4 книжкова, поля 15 мм, Fira Sans (TTF-підмножина латиниця + кирилиця + `ε τ ° … № −`, `tools/make_pdf_fonts.py`;
у PDF — підмножина гліфів, Type0/CIDFontType2). Порядок:

1. **Титул**: «Звіт про термографічне обстеження», таблиця заповнених полів (об'єкт обстеження, виконавець, група,
   викладач, дата звіту), «Опис обстеження».
2. **Термограма N. <файл>** (перша — на титульній сторінці, наступні — з нової сторінки):
   - ІЧ-кадр **як у переглядачі**: палітра, шкала (авто/ручна), ізотерми; об'єкти (колір `#a6ff4d`), хрестики
     Max/Min усередині прямокутників і ліній, маркери Max/Min кадру (якщо увімкнено) — векторно; кадр — растр
     RGB без інтерполяції (`/Interpolate false`, видно пікселі); праворуч — кольорова шкала з підписами меж
     і смугами ізотерм. Поруч — видиме фото (JPEG із файлу без перекодування; якщо pdf-lib не розбирає — без фото).
   - «Параметри зйомки й розрахунку»: дата/час, камера (+ серійний №), кадр, діапазон камери, Max/Min/середня
     кадру (середня — по пікселях у калібруванні); ε, T_відб, T_пов, RH, d, τ. Змінений користувачем параметр —
     з поміткою «(у файлі: …)».
   - «Ізотерми» (лише ввімкнені й коректні): режим, межі, частка кадру.
   - «Результати вимірювань»: як таблиця застосунку (T/сер., Max, Min, параметри, пікселів, примітка); власні
     параметри об'єкта — жирним; значення поза діапазоном/калібруванням — бордовим із приміткою.
   - «Профіль лінії Lk» для кожної лінії — графік T (одиниці показу) за номером точки лінії.
   - «Коментар до термограми» (з діалогу) і «Примітка з камери» (текстовий блок файлу).
3. **Висновок** і рядки підписів «Виконавець» / «Викладач» з іменами.
4. Колонтитул на кожній сторінці: «Аналіз термограм · <об'єкт>», «Сторінка N з M».

Одиниці й мова — поточні в інтерфейсі. Ім'я файлу: `<об'єкт>_<дата>.pdf` (без `\/:*?"<>|` і пробілів;
порожній об'єкт — «звіт»). Метадані PDF: Title, Author, Creator, Language.

## Технічне

- `pdf-lib` 1.17 + `@pdf-lib/fontkit` 1.1 — окремий chunk (≈ 1,1 МБ, 510 КБ gzip), вантажиться `import()`
  у `createReport`; шрифти — `new URL(…, import.meta.url)` (окремі файли збірки). SW передкешує все — звіт
  працює офлайн (перевірено `tools/report_e2e.mjs`).
- Стан переглядачів: кожен `Viewer` реєструє функцію-знімок (`registerReportSource`), діалог читає знімки
  в момент створення. Титульні поля живуть увесь сеанс; виконавець/група/викладач — у `localStorage`.
- Перевірка без PDF-переглядача: `pdftoppm -r 80 -png report.pdf page` (poppler-utils, ставить `setup_sandbox.sh`).
