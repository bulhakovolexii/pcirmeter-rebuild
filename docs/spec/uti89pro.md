# Формат термограм UNI-T (UTi89 PRO та споріднені) — `*.bmp`

Статус: v1 (2026-10-23). Перевірено на 9 файлах UTi89 PRO викладача (`samples/uti89pro/Images/`, 2024–2026 рр.,
поза git), інструмент `tools/dump_uti.py` (`--png` — рендер BMP і сірого з точками). Джерело розкладки — Ghidra-аналіз
`LiveScreen.exe` з інсталятора UNI-T «UTi-Live-Screen» 1.68 (`reference/uti/`, знімок
`reference/uti/LiveScreen.rea-snapshot`), клас `Analysis_Widget`, метод `set_Image_addr` (`0x1400172f0`).

Позначки: **[п]** — перевірено на зразках, **[с]** — прямо видно в коді LiveScreen (але не перевірено, що UTi89 PRO
пише саме так), **[г]** — гіпотеза.

## Камера (посібник користувача, `reference/uti/…Manuals+.pdf`)

- ІЧ-сенсор **80×60** (UFPA, 17 мкм, 8–14 мкм, NETD ≤ 150 мК, ≤ 9 Гц); екран 320×240 (портрет 240×320).
- Діапазон −10…400 °C, роздільність 0,1 °C, точність ±2 °C або ±2 % (більше з двох).
- Налаштування: одиниці °C/°F; курсор (центр, гаряча точка, ROI); палітри Iron Red, Rainbow, White Hot, Red Hot,
  Ice Blue; ε і окремо «температурна компенсація»; тривоги HI/LO; автозбереження. Відбитої температури, відстані,
  вологості **немає**.
- Формат знімків — **лише BMP** (вибору формату немає), на micro SD. USB: режим диска («перегляд і аналіз даних
  у ПК-програмі») і режим камери (трансляція).
- Камера викладача: прошивка **V0.2** (меню «Device Info»); решта збігається з посібником.

## Про програму UTi-Live-Screen

- Інсталятор Inno Setup 6 (`innoextract`). Qt 5 + OpenCV 4.1.2, x86-64. `image_algorithms_lite.dll` — лише
  нейромережеве збільшення роздільності (ncnn, модель Real-ESRGAN `model/unit_srx4_160_realesr.*`), до температури
  не стосується. Прикладів термограм в інсталяторі немає. **[с]**
- Основне призначення — трансляція з камери по USB (UVC, `usb#vid_1d6b&pid_0102`, кадри `Format_Y16`/`YUYV`/`NV12`).
  Знімки з трансляції зберігаються звичайним JPEG (`QImage::save`) **без радіометрії**. **[с]**
- Вкладка аналізу відкриває файли з камери: діалог `Images (*.bmp)`; список файлів береться з теки. **[с]**
  Отже, радіометричні файли камери — **BMP із дописаними даними** **[г для UTi89 PRO]**.

## Висновок для UTi89 PRO [п]

**Файли UTi89 PRO не містять температурної карти кадру.** Точні температури у файлі — лише три:
T max, T min (з координатами) і T центру. Сіре 8-бітне зображення — картинка для показу з нелінійним
контрастуванням (імовірно, вирівнювання гістограми): лінійна інтерполяція між T min і T max, як у LiveScreen,
дає похибку до десятків градусів (центр `20261005_202638`: 43,5 °C за сірим проти 9,8 °C у файлі й на екрані камери).

## Файли UTi89 PRO — варіант 1 [п, 9 файлів]

Розмір завжди **231 013 Б** (`0x38665`). Числа little-endian.

| Зсув | Розмір | Вміст |
|---|---|---|
| `0x00000` | 54 | заголовок BMP: 240×320 (портрет), 16 біт RGB565, без стиснення, рядки знизу вгору; `bfSize` = 153 654 (лише сам BMP) |
| `0x00036` | 153 600 | знімок екрана камери з оформленням (шкала, max/min, дата, батарея) — те, що бачить звичайний переглядач |
| `0x25836` | 3 | нулі |
| `0x25839` | 76 800 | сіре зображення 240×320, 1 Б/піксель, **повернуте на 180°** відносно BMP (піксель екрана (x, y) = `g[76 799 − (y·240 + x)]`) |
| `0x38439` | 512 | палітра 256 × RGB565 — у всіх зразках сіра (`0x1063` … `0xF7DE`), не та, що в BMP |
| `0x38639` | 44 | параметри `P` |

Параметри `P` (зсуви від `0x38639`):

| Зсув | Тип | Зміст |
|---|---|---|
| +0 | uint8 | 0 у всіх зразках [г: одиниці / режим] |
| +1 | int16 | **T max** ×10 °C [п] |
| +3 | int16 | **T min** ×10 °C [п] |
| +5, +6 | uint8 | рівні сірого для T max / T min (255/0; 88/0 у сцені з вузьким діапазоном 3,1 °C) |
| +7 | int16 | **T центру** ×10 °C [п — збігається з показом центральної точки на екрані: 20,3; 9,8] |
| +9 | uint8 | 95 у всіх зразках → **ε × 100** [г — перевірити серією ε] |
| +10 | 4 Б | `02 00 01 00` у всіх зразках (LiveScreen для аналізу вимагає uint32 5 або 6 — ці файли, ймовірно, не відкриє) [г] |
| +14 | 2×uint16 | x, y точки **T min** у системі сірого зображення [п] |
| +18 | 2×uint16 | x, y точки **T max** [п] |
| +22 | 2×uint16 | x, y центру = (120, 160) у всіх зразках [п] |
| +26 | 18 Б | нулі, крім байта +42 = `01` [г] |

- Точка на екрані = (239 − x, 319 − y) [п: маркери max/min у BMP `20261015_221327`]. Координати бувають
  рівні 240 / 320 — на одиницю за межею кадру; обмежувати межами.
- Усі координати кратні 4: сенсор 80×60 (посібник), екран — збільшення ×4 [п].
- T min може бути нижче діапазону −10 °C (−17,7; −18,4) — на екрані тоді «-OL» (`202638`) [п].
- Значення на екрані BMP і в `P` збігаються не завжди: точно (`204613`, `221327`, `203306`) або з різницею
  (`100912`: Max 141,1 на екрані проти 131,0 у файлі; `105526`: 31,7 / 16,8 проти 31,6 / 16,5). Схоже, BMP і дані —
  з різних (сусідніх) кадрів [г]. Вважати джерелом даних `P`.
- Рівні сірого в точках max/min не завжди 255/0 (напр., 146/255 у `203306`) — ще одна ознака іншого кадру або обробки [г].

## Розкладка з коду LiveScreen — варіант 0 (інші моделі UNI-T) [с]

Розміри — для екрана камери 320×240. Числа little-endian.

| Зсув | Розмір | Вміст |
|---|---|---|
| `0x00000` | 54 | заголовок BMP (`BITMAPFILEHEADER` + `BITMAPINFOHEADER`) [г — розмір збігається] |
| `0x00036` | 230 400 | 320×240×3 — кольорове зображення BMP (24 біт) з оформленням (шкала, маркери) [г] |
| `0x38436` | 76 800 | 320×240×1 — «сіре» зображення: індекс палітри 0…255 для кожного пікселя |
| `0x4B036` | 512 | палітра: 256 × uint16 RGB565 (для смуги кольорів) |
| `0x4B236` | 26 | параметри (`P`, див. нижче) |
| `0x4B250` | 98 304 | **256×192 × uint16 — радіометричний кадр**; є лише якщо розмір файлу = `0x63250` (406 096 Б) |

Варіант 1 (третій аргумент `set_Image_addr`; значення береться з налаштування вікна, ймовірно, тип/серія камери) —
інша розкладка: сіре зображення з `0x25839`, палітра з `0x38439`, параметри з `0x38639`, зображення дзеркальне
(координати перераховуються як `319 − x`, `239 − y`). 0x25836 − 0x36 = 153 600 = 320×240×2 — схоже на BMP 16 біт. [г]

## Параметри `P` [с]

| Зсув у `P` | Тип | Зміст |
|---|---|---|
| +0 | uint8 | режим 0/1 — вибирає пункт випадного списку в UI (одиниці? діапазон?) [г] |
| +1 | int16 | **T max**, ×10 °C |
| +3 | int16 | **T min**, ×10 °C |
| +5 | uint8 | індекс сірого, що відповідає T max |
| +6 | uint8 | індекс сірого, що відповідає T min |
| +7 | uint16 | невідомо (ε ×100? відстань?) [г] |
| +9 | uint8 | невідомо [г] |
| +10 | uint32 | тип файлу; програма приймає лише **5 або 6**, інакше «не підтримується» |
| +14, +16 | uint16 | рядок, стовпець точки **T min** (у координатах 320×240) |
| +18, +20 | uint16 | рядок, стовпець точки **T max** |
| +22, +24 | uint16 | ще одна пара координат (центр / курсор?) [г] |
| +42 | uint16 | ×10 — щось виводиться в журнал лише для варіанта 1 (T центру? ε?) [г] |

## Температура [с]

- **Файл з радіометричним кадром** (406 096 Б): `T[°C] = v / 16 − 273,15`, де `v` — uint16 з кадру 256×192
  (тобто кельвіни × 16). Для відображення програма розтягує кадр до 320×240 (індекс `⌊i·4/5⌋`).
- **Файл без кадру**: температура пікселя — лінійна інтерполяція між T min і T max за індексом сірого:
  `T = Tmax − (gmax − g) / (gmax − gmin) · (Tmax − Tmin)`. Точність — 256 рівнів на діапазон кадру.
- Поправок на ε, T відбиту, атмосферу в коді аналізу немає. Імовірно, камера вже записує температуру з ε, встановленим
  під час зйомки (випадок «готові °C»), і перерахунок за новим ε можливий лише наближено. [г]

## Що лишилось з'ясувати (I-19)

1. ~~Чи камера вміє інший формат~~ — за посібником лише BMP. Лишається: чи бувають інші прошивки (V0.2 у викладача).
2. Серія ε: чи +9 — це ε, і чи змінюються T max/min/центру зі зміною ε (камера враховує ε під час зйомки?).
3. Байт +0 і `02 00 01 00` (+10): одиниці °F, режим курсора (центр / гаряча точка / ROI), палітра; де «температурна
   компенсація».
4. Чи відкриває LiveScreen ці файли (Windows-VM).
