Робота ведеться **інкрементами: один інкремент = одна сесія Claude Code**.
Як починати й завершувати сесію — див. «Протокол сесії» в `CLAUDE.md`.
Журнал виконаних сесій, рішень і знахідок — `docs/PROGRESS.md`.

Статуси: ✅ виконано · ▶ наступний · ⏳ заблоковано (чекає на зовнішнє) · ☐ заплановано.
Оцінка — орієнтовна кількість оброблених токенів (переважно кешований контекст).

## Опис інкрементів

Кожен інкремент закінчується, коли виконано **всі** пункти «Готово, коли». Інакше статус лишається ▶,
а в `PROGRESS.md` записується, що зроблено і що лишилось.

### I-04 Каркас проєкту
- (git уже ініціалізовано, гілка `main`; віддаленого репозиторію поки немає — за потреби створити разом з CI.)
- Vite + TypeScript (strict) + Svelte; Vitest; ESLint + Prettier; скрипти `dev`, `build`, `test`, `lint`.
- Структура: `src/core/` (без DOM), `src/ui/`, `src/i18n/`, `tests/`.
- GitHub Actions: lint + test + build на push (деплой — у I-16).
- **Готово, коли:** `npm run lint && npm test && npm run build` проходять; порожній застосунок відкривається в `npm run dev`;
  у `CLAUDE.md` оновлено «Корисні команди».

### I-05 Парсер
- `src/core/parser.ts`: `parseThermogram(ArrayBuffer)` → метадані (`File_Para_t`), блоки (ІЧ, фото, текст, аудіо),
  параметри ІЧ-заголовка, калібрувальна таблиця, `Uint16Array` AD. Чіткі помилки для не-термограм.
- Фікстури: скрипт `tools/export_fixtures.py` пише JSON з очікуваними полями для всіх 26 зразків (з `dump_ir.py`-логіки).
- Ядро компілюється з `lib: ES2023` без DOM (`tsconfig.core.json`): якщо для тексту/назв потрібен `TextDecoder`
  (CP1251?), або оголосити мінімальний тип у `src/core/`, або декодувати вручну — не додавати `DOM` у ядро.
- Тести читають зразки з `samples/`. У git (і в CI) лише `legacy-2013` (7 файлів); `latest-2021` (19) — локально,
  тести на них пропускаються, якщо файлів немає. Фікстури JSON (очікувані поля) можна комітити — вони не містять зображень.
- **Готово, коли:** тести парсера проходять на всіх 26 зразках локально і на 7 у CI; звичайний JPEG дає зрозумілу помилку.

### I-06 Температура
- `src/core/temperature.ts`: τ, LUT, поправка калібрування, радіометричне рівняння, одиниці; векторний перерахунок кадру.
- Вхід — `IrImage` з `parseThermogram` (`params`, `calibration`, `ad`); параметри користувача (ε, T_відб, …) —
  окремим об'єктом, що за замовчуванням береться з `ir.params`. Таблиці атмосфери — з `tools/atmosphere_tables.json`
  (перенести в `src/core/` як TS-константи; файл уже в git).
- Фікстури — розширити `tools/export_fixtures.py` (або окремий скрипт на основі `irtemp.py`) у `tests/fixtures/temperature/`.
- Фікстури з `tools/irtemp.py`: температури у ~50 випадкових пікселях на файл + межі автошкали.
- **Готово, коли:** збіг з `irtemp.py` ≤ 0,01 °C у всіх фікстурах; межі автошкали — 26/26 у межах 0,11 °C від значень камери;
  перерахунок кадру 384×288 < 50 мс у Node.

### I-07 Специфікація функцій
- Джерела: CHM-довідка (en), декомпільовані форми `PCIRMeter.exe`, палітри з `ColorPalette.dll`.
- `docs/spec/features.md`: кожна функція → MVP / v1 / пізніше / не робимо; зафіксувати рішення з викладачем.
- **Вирішено (викладач, 2026-10-22):** температури показуються справжні, без обрізання діапазоном камери;
  значення поза `measurementRange` (−20…150 / 0…400 °C) позначаються «поза діапазоном». Max кадру — справжній (не від 0 °C).
- **Виконано 2026-10-22:** `features.md` погоджено (палітри — таблиці оригіналу; MVP + профіль, ізотерми, видиме фото;
  збереження розмітки — не потрібне). Навчальні функції — відкрите питання до I-15.

## Ризики та пом'якшення

| Ризик | Стан / пом'якшення |
|---|---|
| Калібрування не зберігається у файлі | **Знято**: таблиця й параметри є в кожному файлі (I-02) |
| Нові камери пишуть інший формат | DT-980 (2021) і камери 2013 р. — один формат; нові моделі перевіряти через `tools/dump_ir.py` |
| Неможливо запустити оригінал | **Знято**: UTM + Windows 11 ARM у викладача |
| ΔAD відсутній у файлі (поле 0x5C = 0) | Не трапилось у зразках; R-01 за потреби |
| Правові питання | Декомпіляція для сумісності форматів (Директива ЄС 2009/24/ЄС, ст. 6; аналогічна норма Закону України про авторське право); clean-room; не поширювати код і ресурси оригіналу |
