### I-04 Каркас проєкту

### I-05 Парсер
- `src/core/parser.ts`: `parseThermogram(ArrayBuffer)` → метадані (`File_Para_t`), блоки (ІЧ, фото, текст, аудіо),
  параметри ІЧ-заголовка, калібрувальна таблиця, `Uint16Array` AD. Чіткі помилки для не-термограм.
- Фікстури: скрипт `tools/export_fixtures.py` пише JSON з очікуваними полями для всіх 26 зразків (з `dump_ir.py`-логіки).
- Ядро компілюється з `lib: ES2023` без DOM (`tsconfig.core.json`): якщо для тексту/назв потрібен `TextDecoder`
  (CP1251?), або оголосити мінімальний тип у `src/core/`, або декодувати вручну — не додавати `DOM` у ядро.
- Тести читають зразки з `samples/`. У git (і в CI) лише `legacy-2013` (7 файлів); `latest-2021` (19) — локально,
  тести на них пропускаються, якщо файлів немає. Фікстури JSON (очікувані поля) можна комітити — вони не містять зображень.
- **Готово, коли:** тести парсера проходять на всіх 26 зразках локально і на 7 у CI; звичайний JPEG дає зрозумілу помилку.

### I-10 Параметри об'єкта й одиниці
- Панель «Параметри об'єкта» у переглядачі (кожна вкладка — свої): ε, T_відб, T_повітря, відносна вологість, відстань;
  стартові значення — з файлу; «Скинути до значень із файлу»; змінені поля позначено; τ атмосфери показано (тільки читання).
  `offset` із файлу не редагується (оригінал теж не дає).
- Межі й кроки — як у формі оригіналу (`IRControl1`: `emissNuneric`, `reflecNuneric`, `envNuneric`, `humidNumeric`,
  `distNumeric`): ε 0,10…1,00 (0,01); T_відб −100…2000 °C, T_пов −40…2000 °C (0,1); RH 0…100 % (1); d 0…5000 м (0,1).
  Значення поза межами — попередження біля поля, модель лишається з останнім коректним значенням. Межі — у ядрі.
- Миттєвий перерахунок (без кнопки OK, на відміну від оригіналу): T під курсором, Max/Min, підписи автошкали
  (автошкала — ті самі FPGA_Level/Span в AD, як в оригіналі); ручна шкала зберігає межі в °C і перераховує AD.
- Одиниці (глобально, у шапці; пам'ятаються в `localStorage`): °C / °F / K для всіх температур (показ і введення,
  зокрема ручна шкала), м / фут для відстані (1 м = 3,28084 фут, як в оригіналі). Внутрішньо все — °C і м;
  зміна одиниць не змінює модель (без накопичення округлень).
- Логіка форми (одиниці, округлення, межі, «змінено») — без DOM у `src/ui/params.ts`, тести в Node.
- **Готово, коли:** тести одиниць довжини, меж і логіки форми проходять; смоук-тест UI показує панель параметрів і
  температури в °F; `npm run lint && npm test && npm run build` проходять; викладач перевірив у браузері зміну ε/T_відб
  (перерахунок під курсором і шкали), скидання, перемикання °C/°F/K і м/фут.
- **Виконано 2026-10-22** (крім перевірки в браузері): `PARAM_LIMITS`/`isValidParam` у `temperature.ts`, м ↔ фут у
  `units.ts`, `src/ui/params.ts`, `src/ui/settings.ts` (одиниці + `localStorage`), панель у `Viewer.svelte`,
  перемикачі одиниць у шапці `App.svelte`. Викладач перевірив у браузері — працює (2026-10-22). I-10 ✅.

### I-12 Аналіз: профіль лінії, ізотерми, гістограма
- **Профіль лінії** (MVP): графік T уздовж вибраної лінії (якщо вибрано не лінію — останньої доданої), точки —
  `objectPixels(line)` від початку до кінця, температури — з параметрами об'єкта (як у таблиці). Вісь X — номер точки
  (як в оригіналі), Y — температура в одиницях показу. Наведення на графік — номер, піксель, T і позначка цього пікселя
  на зображенні; Max/Min лінії на графіку. Графік — власний SVG (≤ кількасот точок; без uPlot — менше залежностей,
  смоук-тест через `svelte/server`). v1, що береться тут: «Зберегти профіль CSV» (№, x, y, T).
- **Дві ізотерми** (MVP) — семантика оригіналу (`IRControl1`, `AnalyzeHead_ListVer.processIRImage`): режими «вище» /
  «між» / «нижче», свій колір (за замовчуванням зелений / синій, як в оригіналі), межі в одиницях показу (внутрішньо °C);
  пікселі в межах фарбуються суцільним кольором поверх палітри, ізотерма 1 поверх 2. Порівняння — по °C пікселів
  (рівносильно AD-порогам оригіналу з точністю до 1 AD); «вище» — без верхньої межі (оригінал обрізає межею шкали — [п],
